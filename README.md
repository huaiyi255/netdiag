# netdiag

> 一个 `.bat` 文件搞定"网站打不开"的排查 —— 双击即用，零依赖，逐层定位到底卡在哪一层。

`netdiag` 是给 **Windows** 用的网络故障诊断脚本。它不猜、不玄学，按 **DNS → TCP → HTTP → TLS → 路径/MTU** 的顺序一层层探测，把每一层的结果和耗时摊开给你看，最后给出按优先级排序的修复建议。

适用场景：

- 某个网站打不开，但别的网站都正常 —— 是域名解析问题、端口被封、应用层 5xx，还是证书过期？
- 「同办公室同事能打开，我这台不行」—— 是本地 DNS、代理、hosts 还是 IPv6？
- 「时快时慢」—— 是 CDN 调度、丢包抖动，还是 IPv6 回落卡顿？
- 想把这个现象完整描述给运维/网络管理员，但不知道从哪说起。

---

## 特性

- **单文件、零依赖**：脚本把 PowerShell 部分嵌在自己文件里，运行时自解压执行，不需要 Python / Go / Node / 任何安装包。
- **分层探测**：DNS 解析（系统 + 3 个公共 DNS + DoH 交叉验证）、TCP 握手（不用 ping）、HTTP 应用层（保 Host 换 IP）、TLS 握手与证书、路径追踪、MTU。
- **只读诊断**：不写 hosts、不改系统设置、不动 DNS 配置，跑完就走。
- **结论可追溯**：每条判断都带着证据（哪个 IP、哪个端口、多少毫秒、什么错误码）。
- **输出中文**，排版适合直接截图或复制给同事。
- **自动留档**：每次运行把完整日志写到 `%TEMP%\netdiag-<时间戳>.log`。
- **退出码**可被其他脚本 / 计划任务判断。

## 快速开始

1. 把 `netdiag.bat` 下载到桌面（或任意目录）。
2. 双击运行，输入要排查的域名，回车。
3. 看第 `7. 诊断结论` 段和 `修复建议` 段。

命令行用法：

```bat
netdiag.bat www.example.com
netdiag.bat https://www.example.com/path
netdiag.bat 1.2.3.4
netdiag.bat example.com:8443
netdiag.bat -h
```

不带参数运行会进入交互输入模式，跑完自动 `pause`，双击场景不会一闪而过。

## 参数与示例

| 输入 | 行为 |
| --- | --- |
| `www.example.com` | 未指定协议，同时测 HTTPS(443) 和 HTTP(80) |
| `https://www.example.com/path` | 只测 HTTPS，业务路径为 `/path` |
| `http://www.example.com` | 只测 HTTP |
| `1.2.3.4` | 跳过 DNS，直接对 IP 探测 |
| `example.com:8443` | 只测 8443 端口 |
| `-h` / `--help` / `-?` | 打印用法 |

## 输出结构

脚本固定输出 7 段，从上往下就是排查顺序：

| 段 | 内容 |
| --- | --- |
| `0. 输入解析` | 最终认定的主机、协议、端口、路径（先确认没被自己输错） |
| `1. 本机环境` | 网卡与 IP、默认网关、本机 DNS 服务器、代理设置、hosts 命中、系统时间偏差 |
| `2. DNS 解析` | 系统解析结果；再用 223.5.5.5 / 119.29.29.29 / 180.76.76.76 交叉验证；CNAME 与 CDN 判定；解析失败时用 DoH 反证"域名是否真的没了" |
| `3. TCP 端口探测` | 逐个 IP × 端口做 TCP 握手（3 次采样，给出 min/avg/max 抖动）；区分"被 RST 拒绝"和"SYN 静默超时" |
| `4. HTTP/HTTPS 探测` | 用 `curl --resolve` **保 Host 换 IP**，拿到状态码、耗时、连接耗时、字节数、页面标题、Server 头；多个 IP 内容不一致时提示 CDN/劫持 |
| `5. TLS / 证书` | 握手是否成功、证书链、SAN、有效期剩余天数、是否还在用 TLS 1.0/1.1 等老协议 |
| `6. 路径与 MTU` | 整体不通时才触发：tracert 看断在第几跳；MTU 黑洞时二分探测可用载荷大小 |
| `7. 诊断结论` | 现象归纳 + 根因判断（标注置信度）+ 按 P0/P1/P2 排序的修复建议 |

## 退出码

| 退出码 | 含义 |
| --- | --- |
| `0` | 未发现明显异常 |
| `3` | 发现问题（有异常结论或 P0/P1 建议） |
| `1` | 输入错误（URL/域名格式问题、参数不合法） |
| `2` | 内部错误（脚本自身异常） |

## 常用结论对照表

| 现象 | 通常意味着 |
| --- | --- |
| DNS 全部失败，DoH 也失败 | 域名不存在 / 已下线 / 拼错了 |
| DNS 失败，但 DoH 能解析 | 本地 DNS 坏了或 DNS 服务器不可达 → `ipconfig /flushdns`、换 DNS |
| 不同 DNS 返回不同 IP | CDN 调度（正常）或 DNS 污染（异常） |
| TCP 被 RST 拒绝 | 端口没监听 / 服务没起 —— 不是"被封" |
| TCP SYN 静默超时 | 防火墙 drop / 中间设备拦截 / 线路问题 |
| 80 通、443 不通 | 整机没被封，是该节点的 443 服务或策略问题 |
| TCP 通、HTTP 无响应 | 服务端应用层卡死，或中间有透明代理/网关 |
| 证书快过期 / 证书名不匹配 | 浏览器报"不安全"的直接原因 |
| 路径在某跳之后全 `*` | 从那一跳开始丢包/被拦，可结合 MTU 判断是否分片黑洞 |
| IPv4 通、IPv6 不通 | 浏览器先试 IPv6 卡住再回落，表现为"时快时慢" |

## 局限性

- **需要 Windows 10 1803+**：HTTP 层依赖系统自带的 `curl.exe`。没有 curl 时会给出提示并跳过 HTTP 探测，其余层照常。
- **TLS 检测依赖 Schannel**：某些受限/无凭据的运行环境（如部分远程会话、沙箱）无法建立 TLS 握手。脚本会识别这类错误并标注"本机 TLS 组件不可用"，**不会**把它误判成目标站点故障。
- **MTU 与路径追踪依赖 ICMP**：很多服务器和网络设备默认禁 ping，探测会被跳过，这不代表故障。
- **不做抓包**：想看 TCP 重传/分片细节请用 Wireshark；想看持续丢包请用 MTR/WinMTR。
- 探测全程只读，**不会**修改任何系统配置。
